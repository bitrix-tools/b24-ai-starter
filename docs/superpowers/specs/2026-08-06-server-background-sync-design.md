# Серверная фоновая синхронизация Точки

## Цель

Настройка «Включить постоянную синхронизацию» должна управлять серверной
синхронизацией выписки. Она должна работать при закрытом приложении, а интервал
должен браться из сохранённого значения 3–180 минут.

## Текущее состояние

- Клиентский таймер работает только при открытом дашборде.
- `sync_tochka_background` умеет синхронизировать подключённые порталы, но не
  учитывает пользовательскую настройку и интервал.
- На production отсутствует cron для запуска команды.
- Push-доставка Точки отключена.

## Архитектура

1. Серверный cron запускает `sync_tochka_background` каждую минуту под
   неблокирующим `flock`.
2. Команда выбирает только порталы, у которых:
   - учётные данные Точки подключены;
   - `client_auto_sync_enabled = true`;
   - с предыдущей попытки прошло не меньше
     `client_auto_sync_interval_minutes`.
3. Временем предыдущей попытки служит `TochkaCredentials.updated_at`. Команда
   обновляет его перед запросом к банку, а успешная синхронизация обновляет его
   повторно при сохранении токена. Это предотвращает запрос каждую минуту после
   ошибки и не требует миграции базы.
4. Параметр `--force` позволяет администратору вручную синхронизировать все
   подключённые порталы независимо от настройки и интервала.
5. Клиентский таймер сохраняется: при открытом приложении он обновляет интерфейс
   сразу, а сервер обеспечивает работу после закрытия.

## Интерфейс

- Флажок переименовывается в «Включить фоновую синхронизацию».
- Подсказка сообщает, что синхронизация работает на сервере даже при закрытом
  приложении.
- Поле интервала остаётся единым источником интервала для клиента и сервера.
- Статус больше не утверждает, что после закрытия приложения запросы
  прекращаются.

## Ошибки и безопасность

- `flock` не допускает одновременных запусков cron.
- Ошибка одного портала не останавливает остальные.
- После ошибки повтор выполняется не раньше выбранного интервала.
- Истёкший OAuth-токен переводит подключение в отключённое состояние по текущей
  логике команды.
- В cron и логах не выводятся секреты.

## Production

- В root crontab добавляется идемпотентная строка запуска раз в минуту.
- Вывод пишется в `/var/log/tochka-sync.log`.
- Для текущего портала настройка включается с интервалом 15 минут.
- После установки выполняется принудительный контрольный запуск.

## Проверка

- Выключенная настройка исключает портал из обычного фонового запуска.
- Включённый портал, которому ещё рано синхронизироваться, пропускается.
- Наступивший интервал запускает синхронизацию.
- `--force` запускает подключённый портал независимо от настройки.
- Два одновременных cron-запуска не выполняют синхронизацию параллельно.
- После закрытия приложения новый платёж появляется после следующего
  серверного интервала.
