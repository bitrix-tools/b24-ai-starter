# 🧠 Промпт для AI-агента: настройка RabbitMQ

## Контекст
- Репозиторий: `b24-ai-starter`
- Цель: включить и настроить RabbitMQ для фоновых задач, при необходимости запустить/остановить сервис вручную.
- Инструкции по инфраструктуре: `instructions/queues/server.md`, `README.md` (раздел «Очереди и RabbitMQ»)

## Задачи для агента
1. **Проверить, активирован ли RabbitMQ**
   - Загляни в `.env` (или `versions/<name>/.env`) на наличие `ENABLE_RABBITMQ=1`.
   - Если значения нет — предложи пользователю включить через `make dev-init` или вручную.

2. **Настроить учётные данные**
   - При автоматическом режиме `dev-init` сам генерирует логин/пароль. Сохрани их в `.env`.
   - При ручном вводе проконтролируй наличие `RABBITMQ_USER`, `RABBITMQ_PASSWORD`, `RABBITMQ_PREFETCH`, `RABBITMQ_DSN`.

3. **Запуск и остановка**
   - Для ручного старта используй `make queue-up`.
   - Для остановки — `make queue-down`.
   - Основной стек (`make dev-php` / `dev-python` / `dev-node`) сам добавляет профиль `queue` при `ENABLE_RABBITMQ=1` — проверь значение в `.env`.

4. **Проверить доступность**
   - AMQP: `amqp://rabbitmq:5672`
   - Панель администратора: `http://localhost:15672` (логин/пароль из `.env`)
   - Выполни `docker compose ps` и убедись, что контейнер `rabbitmq` в статусе `Up`.

5. **Синхронизация между версиями**
   - Если пользователь работает с `versions/<name>/`, все команды выполняй в контексте выбранной версии.
   - Объясни, что изменения `.env` в корне и в версиях не синхронизируются автоматически.

6. **Подсказать дальнейшие шаги**
   - Напомни прочитать инструкции по конкретному стеку (`queues/php.md`, `queues/python.md`, `queues/node.md`).
   - Если появляются воркеры, предложи добавить отдельные Docker-сервисы или make-цели.

## Важные предупреждения
- Не запускай RabbitMQ без `ENABLE_RABBITMQ=1`: иначе сервис не будет конфигурирован, а команды агентов могут зависнуть.
- При работе с версиями всегда уточняй у пользователя, где именно нужно включить очередь (корень vs `versions/v*`).
- После изменения `.env` обязательно перезапускай Docker-стек, иначе профиль `queue` не подтянется.
